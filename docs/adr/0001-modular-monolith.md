# ADR-001：采用模块化单体

- 状态：已接受
- 日期：2026-09-01

## 决策

平台使用一个 Next.js App Router 应用、一个 PostgreSQL 数据库和一套认证体系。账本、儿童保健、衣柜、消耗品、成长日志和系统管理作为独立业务模块存在于同一仓库中。

每个模块只能通过 `modules/<module>/index.ts` 暴露公共能力。页面和接口负责输入输出，业务规则放在 Service 中，持久化操作放在 Repository 中。跨模块写操作由 `application/` 下的编排服务发起，并在同一个数据库事务内完成。

## 原因

- 当前数据规模不需要微服务的独立伸缩与运维成本；
- 组合记账需要账本与多个业务模块保持强一致；
- 单仓库便于多个 Agent 按目录边界并行工作；
- 清晰的模块接口保留未来拆分服务的可能性。

## 约束

- 页面、Server Action 和 Route Handler 不直接访问 Prisma；
- 模块不得导入其他模块的私有目录；
- 跨模块写入不得在页面层拼接；
- 所有主要业务数据必须带 `householdId`。
