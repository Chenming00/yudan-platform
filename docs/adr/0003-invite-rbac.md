# ADR-003：邀请码注册与服务端 RBAC

- 状态：已接受
- 日期：2026-09-01

## 决策

平台关闭公开注册。新身份首次进入平台时必须提交有效、未过期、未撤销且未被消费的邀请码；已有平台用户正常登录时不再要求邀请码。

身份提供方采用 Supabase Auth 的 GitHub OAuth，并使用 Next.js 服务端 PKCE 回调建立 Cookie 会话。Supabase 负责证明用户身份，平台数据库负责判断该身份是否允许注册、属于哪个家庭以及拥有哪些权限。

`William.chen@utah.edu` 是初始超级管理员标识。系统只在服务端使用认证提供方已验证并标准化后的邮箱执行幂等引导，不能信任客户端提交的邮箱或角色。

授权由全局角色、家庭成员角色和权限码共同决定。所有读写入口都必须在服务端调用统一的 `authorize` 能力，并将 `householdId` 纳入查询条件。

## 最低角色

- `SUPER_ADMIN`：平台级管理；
- `OWNER`：家庭空间管理；
- `EDITOR`：业务数据读写；
- `VIEWER`：只读。

邀请创建、邀请消费、角色变更、用户停用、权限拒绝和敏感数据访问写入统一审计日志。
