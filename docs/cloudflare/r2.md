# Cloudflare R2 资源部署

应用运行在 Vercel，文件正文由浏览器直接上传到 Cloudflare R2 私有桶。Vercel 只创建短时签名、读取最多 32 字节文件头并维护 Supabase 中的资源状态，不代理完整文件。声明为公开的资源通过校验后才由服务端复制到公开桶。

## Bucket

建议建立两个 Bucket：

- `yudan-private`：儿童保健、衣柜、家庭照片和附件，禁止公开访问；
- `yudan-public`：确实需要公开展示的资源，通过 Cloudflare 自定义域名访问。

浏览器不直接写公开 Bucket，避免未确认或伪造内容在校验前公开。

生产环境不要启用私有 Bucket 的 `r2.dev` 地址。公开 Bucket 使用自定义域名；`r2.dev` 只用于临时开发验证。

## R2 API Token

创建仅限上述 Bucket 的 Object Read & Write Token，并在 Vercel 服务端配置：

```text
CLOUDFLARE_ACCOUNT_ID
R2_ACCESS_KEY_ID
R2_SECRET_ACCESS_KEY
R2_PRIVATE_BUCKET
R2_PUBLIC_BUCKET
R2_PUBLIC_BASE_URL
CRON_SECRET
```

这些变量都不能使用 `NEXT_PUBLIC_` 前缀。数据库只保存 Bucket 和 Object Key，不保存短时上传或下载 URL。

## CORS

将 [r2-cors.json](./r2-cors.json) 中的域名替换为正式域名和需要使用的 Vercel Preview 域名，然后在 R2 Bucket 设置中配置。仅允许 `PUT`、`GET` 和 `HEAD`，允许 `Content-Type` 请求头并暴露 `ETag`。

Presigned URL 是 Bearer Credential，上传有效期为 10 分钟，私有下载有效期为 5 分钟。签名必须使用 R2 S3 API 域名，不能使用公开自定义域名。

## 生命周期

```text
PENDING --确认大小/MIME/文件头--> READY
PENDING --超过有效期------------> DELETE_PENDING
READY   --用户删除---------------> DELETE_PENDING
DELETE_PENDING --R2 删除成功-----> DELETED
```

Vercel 每天调用 `/api/internal/media/cleanup`，并使用 `Authorization: Bearer $CRON_SECRET`。清理失败会记录尝试次数和简短错误，后续继续重试。

## 发布检查

1. 先在 Preview 环境创建测试 Bucket 和独立 Token；
2. 验证允许类型能直传，错误扩展名、超限大小和伪造文件头会失败；
3. 验证另一个家庭无法确认、读取、关联或删除资源；
4. 验证私有下载 URL 过期后不可访问；
5. 验证逻辑删除立即从业务列表消失，物理删除失败后可重试；
6. 最后才把正式 R2 变量配置到 Vercel Production。

参考：[R2 Presigned URLs](https://developers.cloudflare.com/r2/api/s3/presigned-urls/)、[R2 CORS](https://developers.cloudflare.com/r2/buckets/cors/)、[R2 S3 API compatibility](https://developers.cloudflare.com/r2/api/s3/api/)。
